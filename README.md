# Meme Scout · 自动扫链排雷

本机浏览器入口：<http://127.0.0.1:3000/>。无需输入合约地址。

首次安装（Node.js 22.13+）：

```sh
git clone git@github.com:hanguang254/MEME-scout.git
cd MEME-scout
npm --prefix dashboard ci
cp dashboard/.env.example dashboard/.env.local
chmod 600 dashboard/.env.local
```

在 `dashboard/.env.local` 填入自己的 `GMGN_API_KEY`；`X_BEARER_TOKEN` 可选。之后在仓库根目录执行：

```sh
npm run dev
```

也可以进入 `dashboard` 运行同一命令。已有 `dashboard/.env.local` 时不要重新复制模板覆盖配置。

打开面板就会看到自动发现的候选。服务运行期间持续监控；关闭浏览器不会停止服务，终端按 `Ctrl+C` 停止。电脑关机、休眠或停止进程期间不监控。只监听本机，不向云端发布。

## 怎么用

1. 默认监控 Robinhood Chain：合并 Robinhood Trenches 热门交易、早期 Radar、LIVE TAPE 买入触发和 GMGN 1h 热门榜，用 DexScreener 批量补市值。
2. 默认范围：市值 $10,000–$5,000,000，流动性至少 $5,000；可点「筛选」修改。未知市值不混入低市值结果。最多展示 40 个符合条件的候选，其中最多 10 个位置优先给最近 2 分钟的合格 TAPE 买入。
   列表可切换「热度」和「最新」：热度是发现接口给出的原始顺序（追踪钱包买家数降序，相同则成交额降序），最新按建池时间从新到旧。切换只重排已发现的候选，不重新发现也不清空已有报告。
3. 可切换 Solana、BNB Chain、Base、Ethereum。一次监控一个选定链；这些链使用 GMGN 热门榜。
4. 点击任意候选查看自动报告：合约权限、LP 锁仓/销毁证据、卖出限制、钱包分布、持有地址数、开发者发币历史、代币年龄、5 分钟盘面、钱包分类、同图代币数与 GMGN 浏览数。Robinhood 币还展示追踪样本中的早期买家与资金跟随线索。
   每行的图标标记按颜色分级；鼠标悬停任意标记会显示该图标的含义、原始证据逐条与来源。
5. 「暂停/恢复」控制监控。「导出证据」保存该币完整 JSON 报告及来源响应。
6. 「数据连接」可配置 X 的只读 Bearer Token。GMGN Key 从本机配置读取，不回显；仓库不包含任何实际 Key。X 需要另外的接口权限和额度，GMGN Key 不能用于读取 X。

## LIVE TAPE 怎么参与扫币

- 面板展示 Trenches 追踪钱包的 BUY / SELL、金额与价格、交易员及钱包、FOMO 主页、CA 和交易链接。可按买卖方向、币名、交易员或地址过滤；「查看排雷」跳到对应候选。成交经来源推送通道即时到达，通道不可用时自动退回定时读取。
- FOMO 链接是交易员主页，钱包地址是交易员链上地址，CA 是代币合约，三者分别显示。粉丝数是来源报告的数据，不代表独立买家数量。
- 最近 120 秒、`priced=cash_leg`、金额和价格大于零、明确非股票且 `flags=[]` 的买入，才会触发市值核验；还需通过当前市值和流动性门槛。转入伪装买入、planted 等来源异常仍展示，不触发自动候选。没有来源标记不等于已证明真实交易或币安全。
- 同钱包多笔交易分为成交笔数与去重钱包数，不加到榜单的 1h 净流入。按上游事件 ID 去重，同一 tx 的不同成交保留；同 ID 修订替换原记录。
- 已入选的交易观察最多保留 15 分钟供队列核验；只有最近 2 分钟买入享有优先席位和扫描优先级。其市值每 60 秒复核，报价超过 90 秒时撤掉 TAPE 提供的候选资格；若另在热门榜，仍可由榜单入选。
- 风险队列优先处理有近期买入且未扫描/报告过期的币，连续两个优先任务后让一个普通候选执行。180 秒内报告复用，短暂离榜再回来不会重复耗费请求。

## 监控与证据边界

- 风险字段按真实返回值显示。GMGN 的权限标记、整数枚举、锁仓汇总均参与解析；相互冲突的来源会同时展示。顶部显示“多少项有证据 / 多少项未核验”，类目覆盖数不代表逐项完成。
- GoPlus 请求成功但缺关键字段会标记“部分数据”。源码未被来源收录、来源未识别可检测交易池、API 出错、X 未配置等原因分别说明，不把缺字段变成“无风险”。
- 持有地址数、GMGN 浏览数、同图代币数三项只作观察，永远显示为“已取得观察值”，不参与风险判级。持有地址数是**地址数不是人数**——同一个人可以持有多个地址，交易池与合约地址是否计入来源没有说明；来源在 `holder_count` 与 `stat.holder_count` 两处各报一次，两个快照可能差几个地址，不一致时两个都显示且不取平均。浏览数没有公布统计窗口，也没说明同一访客重复打开是否只算一次，不能读成“多少个人在看”；它归入市场类而非讨论类，否则一个浏览计数会让“X 讨论”这一类凭空算作已有证据。同图代币数常见于仿盘和批量发币，但也可能是同一团队的系列币或来源指纹碰撞，来源未公布比对方式与是否含本币。
- 代币年龄、跑路评分、5 分钟盘面和钱包分类来自已取得的来源字段，不额外发请求。年龄本身不判定风险，只说明其余指标的统计窗口有多短；跑路评分是来源的历史统计，低分不等于安全。5 分钟涨跌只由窗口首尾两点算出，看不到期间的 K 线形态，行情不参与风险判级。狙击/捆绑/老鼠仓等分类是来源给出的钱包个数，来源没有公布分母，标签不等于对钱包身份或作恶的认定。
- Robinhood 深扫增加官方 RPC 的固定区块 `eth_getCode` 与原代币 CA 的 `owner()` 只读查询，以及 Blockscout 代理/实现元数据；浏览器拒绝或来源缺失会保留错误。RPC 还能精确识别标准 ERC-1167 与 0age/Solady 44 字节最小克隆并提取实现地址；未匹配不代表非代理。Owner 返回零地址不代表其他权限已撤销，最小克隆也不直接等于可升级。
- GMGN `lock_summary` 的锁定/销毁比例是来源汇总。尤其 Uniswap V4 仍需核验具体流动性头寸的控制权与锁定期限，未取得时明确保留缺口。代币跳转（候选详情、交易流、开发者历史币）统一打开 GMGN；FOMO、钱包与交易证据链接保留对应来源。
- **表格里的市值、成交、流动性是行情值，不是报告值**：由 DexScreener 每 6 秒单独重取，覆盖面板支持的全部五条链，不用 Key，也不占 GMGN 额度。数字变动时会闪一下中性底色，只表示「这个数刚刚换了」，不表示涨跌。市值行下方是两个锚点：「首次」是第一份报告写成时的市值，「核验时」是最近一份报告写成时的市值。
- **来源每约 32 秒才换一次数，所以这不是逐笔实时。** 实测：两个互不相关的 Solana 活跃 meme 对（5 分钟内分别成交 311 笔和 558 笔），在完全相同的时刻换数，间隔 31.8 秒和 32.1 秒——那是 DexScreener 的服务端定时刷新，不是逐笔推送，轮询再快也只会拿回同一份字节。6 秒这个间隔控制的是**本机自己那段延迟**：来源一发布，最多 6 秒内出现在页面上（原来是 15 秒）。整页两个批请求、每分钟 20 次，对方限额约 300 次/分。要做到真正的逐笔，需要另接数据源（Robinhood 链已有 LIVE TAPE 的推送通道，Solana 需要另接报价接口），目前没有接。
- 两个锚点量的不是同一件事：重扫约 101 秒一轮，每轮都会把「核验时」重新锚到当时的市值，所以它旁边的百分比**最多只能反映几分钟的行情**；「首次」不随重扫改变，是页面上唯一比这更长的参照。只有出过两份以上报告时「首次」才单独成行，否则它和「核验时」是同一个数。该币掉出名单超过 15 分钟、报告被清理后锚点才重新计起（沿用已有的报告保留规则，不另设一套）；锚点是**第一份报告**的时间而不是发现该币的时间——发现早于扫描——所以悬停里显示的是锚点的实际时间。
- 涨绿跌红只表示方向，用的是行情配色，与风险配色完全分开：一个合约仍可增发的币涨 20% 不是好消息。颜色按四舍五入后的数字判定，小到显示为 0.0% 的波动保持灰色。
- 行情重取只更新已在榜候选的数字，**不增删、不重排候选**——名单仍由每 60 秒的发现决定。否则市值在筛选边界上下摆动的币会每 15 秒进出一次列表，还会让已经花掉限流额度扫完的报告因为瞬时掉出名单而被丢弃。
- 完全稀释估值（FDV）与市值同时保留：两者之差是未计入流通的供应量，来源既没公布它用的流通量，也没说明差异原因，所以不互相替代，FDV 在市值的悬停说明里显示。
- **报告里的证据不随行情走**：浏览数、流动性深度、5 分钟盘面都是该币被重扫那一刻的快照，只在重扫时更新（稳态约 101 秒，最长可超过 3 分钟）。所以标记里的「核验 $80.1K」与表格里的「LP $80.15K」对不上是正常的，不是错误——它们是同一个量的两个时间点，标记上都注明了是核验时的值。
- 热门发现每 60 秒调度。深度检查逐个串行执行，但每个币内部分两路并行：GMGN 链（基本信息 → 合约/持有人 → 开发者，后面的请求真的需要前面的返回值）与 GoPlus/Blockscout/RPC/X 同时进行，请求总数不变。
- GMGN 请求由限流器按**调用开始时间**计量，目标 45 次/分。计量的是间隔而不是「每次之后睡多久」：来源答得慢时那段时间已经付过间隔，不再叠加一次睡眠。扫描循环自己不再插入间隔，只有一次都没打到限流器的扫描才补 1 秒下限，避免空转。
- GMGN 没有公布限额，所以速率不靠猜：**撞到第一次 429 就降到 25 次/分并保持到重启**，界面顶部说明降速时间和后果。限流器不会自动往回试探——省下的几秒不值得再触发一次 5 分钟的全局冷却。命中冷却时整个循环睡到冷却结束，不再逐个候选去撞；超时会记为来源错误。
- GMGN 限流导致基本信息都取不到时，本次不写报告：一份缺少合约、持有人、开发者的空壳会盖上新的核验时间，把上一份真实证据藏在“刚刚查过”后面三分钟。界面改为提示该币未重查及原因，旧报告原样保留。
- Blockscout 连续三次失败后暂停请求 30 分钟，期间该来源如实显示为“暂停请求至 …、本次未取得”，不显示成已核验，也不占用扫描时间。
- LIVE TAPE 优先走来源的推送通道（`wss://rhtrenches.com/ws`），成交在上游落库后即时到达，不再等固定间隔；本机再用 SSE 推给页面，取代原来的 3 秒轮询。面板顶部显示当前是「推送中」还是「轮询 N 秒」。推送到达后 200 毫秒内的连发会合并成一次界面更新，安静期的首笔立即送达。
- 推送不是全量订阅：它带新成交，也带来源对已推送行的事后改判（`labels` 帧），但仍受来源索引延迟影响（连接时来源自报的落后秒数显示在面板上，那是建立连接那一刻的快照，不是本次成交的实测延迟）。推送通道 8 秒内没建立、或连续断开，就自动退回每 5 秒 REST 读取，恢复后再切回；页面的 SSE 断了也会自动退回 3 秒轮询。
- **推送和请求回包走的是两条不同的连接，到达顺序不等于产生顺序。** 每份快照在生成处打一个递增序号，页面丢掉比手上更旧的那份。否则切链前一瞬间刷出去的那帧可能在切链回包之后才被处理，把上一条链的名字和整张候选表重新贴回页面，要等下一次推送（切到非 Robinhood 链后只剩 6 秒一次的行情心跳）才恢复——看起来就是「点了切换没反应，刷新才有用」。快照另带一个进程标识：数据服务重启后序号从头开始，页面据此重置水位，而不是把新进程的帧全部当旧帧丢掉。
- 改判即时生效：来源把一笔买入改判为转账伪装、planted 或新池等标记时，该行当场更新，被撤回的买入立即失去候选席位与扫描优先级；标记被撤销的买入也会重新参与准入。改判本身不算一次完成的重读。
- `labels` 帧只列出来源当前打了标记的 ID，因此「不在帧里」只在该帧覆盖的 ID 区间内等于「标记已撤销」。本机保留的 400 条比来源的标记窗口更长，区间以外一律不动——宁可多留一条旧警告，也不因为窗口边界把真实标记悄悄抹掉。区间以外只能靠每 60 秒的全量重读复核，长时间没有完成会单独提示「兜底全量重读未完成」，这与「漏掉新成交」是两回事，分开显示。
- 推送通道会把股票代币一并推来，与 REST 读取的 `stocks=false` 窗口保持一致，这些行在入库前丢弃。
- 初始化读最近 400 条，通常重叠读最近 60 条；中断后补读 400 条仍无重叠会提示可能遗漏。界面展开最多显示当前筛选的最近 100 条，后端最多保留 400 条。
- 推送在线时不再按「最后一条成交的时间」判断延迟：没有成交不等于掉线。延迟状态改由通道状态与读取是否按时完成决定。
- 列表顺序不含任何风险信号：无论按热度还是按最新排，严重风险的币都可能排在体检干净的币前面。按风险看要用「高风险」页签过滤。
- 「最新」排的是**交易对/池的创建时间**，不是代币合约的部署时间，换池会得到更“新”的时间。取不到创建时间的候选保留它在热度顺序里的位置，不猜测、也不当作新币。合约创建时间只有深扫后才有（`info.creation_timestamp`），不参与列表排序。
- 排序在截断到 40 个之前执行，所以热度排名靠后的新币也能进入列表。热度次键使用的成交额窗口不统一：DexScreener 匹配到的是 1h 主池，仅由 GMGN 补上市值的仍是来源各自的 1h 或 24h 值，跨窗口比较会抬高 24h 那批。
- 未扫描的币会排队。3 分钟前的报告标记过期待重查。重扫只沿用两次扫描之间不会变化的证据（GMGN 合约权限、开发者发币历史），行情、市值和持有人分布始终重取；开发者历史只在创建者地址一致时沿用。
- **首扫只花两次 GMGN 调用**（基本信息 + 合约权限），持有人分布与开发者发币历史留到下一轮。把四次调用花在队首的币，正是队尾的币要等六分钟才有任何结果的原因。延后的两项在报告里记为 `deferred` 并写明「首扫优先取得合约权限，本项留到下一轮补齐」——是本机主动延后，不是来源没返回，更不是没风险；这两类的覆盖数照实少算。
- 带延后项的报告不等满 3 分钟就重新排队（仍受同一个币 60 秒内不重复尝试的限制），排在完全没有报告的币后面。否则首轮跑完后循环会带着已知缺口空转两分钟。
- 沿用的条目保留它原本的取得时间，不盖成本次时间；报告头部注明沿用了哪些来源、取得于何时、比本次核验早多久。上次失败的项一律重取，不会被当作已核验结果继承，缺口照旧显示。
- 按 38 个候选、45 次/分估算：全部币拿到首份报告约 101 秒，补齐延后项约再 152 秒，之后稳态一轮约 101 秒。这些是调用预算算出来的上界，不是保证——来源变慢、限流降速或熔断时仍会有币超过 3 分钟没有重查，过期标记会如实显示。
- 结果分为严重风险、高风险、需要警惕、证据不足和已查项未触发；**没有“保证安全”或自动买入**。六类覆盖数只表示已有部分证据，不是完成审计的百分比。
- LP 持有人份额不等于实际仍锁份额。没有总量/期限对应证据时，锁定比例保持未知；RugCheck 部分池比例不能代表全池。
- Top 地址只基于返回样本。排除已识别池/销毁地址后仍可能包含未识别合约。共同出资可能来自交易所，不证明同一控制人。
- 网站追踪的钱包不是全链持有人；跟随顺序不证明跟单关系。Robinhood Trenches 是第三方社区工具，不是 Robinhood 官方审计服务。
- X 近 7 天最多 100 条按 CA 检索的帖子，不是随机样本。展示去重作者、复读率、新号和时间集中线索；不能确认真人身份，也不输出真人概率。没有 X 凭据时明确显示未连接，其他扫描继续。
- 各来源有缓存、覆盖与识别差异。税率和卖出检测冲突会保留；请求时间不等于链上检测时间。最终买卖由用户自己决定。

## 配置与启动

### 云端部署状态

当前版本保留持续扫描后台：关闭网页后，运行中的 Node 服务仍会扫描。**这份代码尚未适配为可直接导入 Vercel 的完整应用**：构建使用 Vinext / Cloudflare，数据服务需要常驻进程，状态存于内存。

如果使用 Vercel Hobby，内置 Cron 最快每天一次，无法直接承接现有 5 秒交易流和 60 秒候选发现。Vercel 提供的其他后台执行能力也有独立限额；不应依赖打开网页来假装实现全天监控。要保留当前节奏，建议把面板部署到 Vercel，扫描服务放在常驻主机；纯 Vercel 方案则需要另行设计持久化状态、分批任务与额度预算。

依据：[Vercel Cron 限制](https://vercel.com/docs/cron-jobs/usage-and-pricing)、[Vercel Workflows 额度](https://vercel.com/docs/workflows/pricing)。当前没有启用云端部署、自动收费资源或定时任务。

项目内 `.env.local` 权限为 `0600`，已被 `.gitignore` 排除。支持 `GMGN_API_KEY`、`X_BEARER_TOKEN`，不要使用 `VITE_` 或 `NEXT_PUBLIC_` 前缀。GMGN runner 限定只读白名单并移除私钥，项目 Key 优先于 CLI 全局配置。

GMGN CLI 随项目依赖安装。需要在 Codex 中使用 GMGN skills 时，可在根目录另外运行 `npx skills add GMGNAI/gmgn-skills`。本地安装目录 `.agents/skills` 不提交，`skills-lock.json` 保留已有安装来源记录。面板运行本身不依赖该技能目录。

若重新复制项目到另一台电脑：Node.js 22.13+，执行 `npm ci` 后配置自己的 Key。`npm run dev`/`npm start` 会同时启动本机数据服务与页面。

## 验证和代码

```sh
npm test
npm run typecheck
npm run lint
npm run build
```

- `dashboard/scanner/providers.mjs`：来源接口、GMGN 队列、限流和失败处理。
- `dashboard/scanner/risk.mjs`：三态解析、可核验风险与讨论样本规则。
- `dashboard/scanner/profile.mjs`：年龄、跑路评分、5 分钟盘面、钱包分类、持有地址数、浏览数与同图代币数的取值规则——全部取自已经拿到的响应，不发新请求。
- `dashboard/scanner/values.mjs`：各模块共用的数值、布尔、比例解析。
- `dashboard/scanner/monitor.mjs`：独立发现/扫描/行情循环、缓存与配置代际隔离。行情重取写的是候选的替换副本而不是原对象——每份报告都持有它当时那个候选的引用，就地改写会把「结论是在多少市值上作出的」悄悄换成当前值。
- `dashboard/scanner/tape.mjs`：交易 ID 去重、异常修订撤销、买入触发规则。
- `dashboard/scanner/server.mjs`：本机 API、设置与报告下载。
- `dashboard/app/`：浏览器工作台。
- `research/`：网站、风险数据源和 X 官方文档调研。

当前没有请求钱包签名、交易、私钥输入或自动下单路径。源码 lint 针对本项目 app/scanner/tests/lib；保留的上游 Shadcn 组件目录不在此 lint 命令范围内。
